-------------------------------------------------------------------------------
١. تشفير البيانات أثناء الراحة (Encryption at Rest)
-------------------------------------------------------------------------------
• تفعيل TDE على قاعدة البيانات:
  - يتطلب SQL Server Enterprise Edition
  - أنشئ Master Key و Certificate ثم Encryption Key
  - نفّذ: ALTER DATABASE [TicketingSystem] SET ENCRYPTION ON;

• إذا كان لديك Standard Edition فقط:
  - استخدم BitLocker على مستوى القرص
  - أو فعّل Transparent Data Encryption عبر أدوات طرف ثالث

-------------------------------------------------------------------------------
٢. شهادة SSL/TLS
-------------------------------------------------------------------------------
• في بيئة داخلية بدون CA خارجي، أنشئ شهادة ذاتية التوقيع:
  1. افتح PowerShell كمسؤول
  2. نفّذ:
     New-SelfSignedCertificate -DnsName "ticketing.nazaha.local" -CertStoreLocation cert:\LocalMachine\My -KeyExportPolicy Exportable
  3. صدّر الشهادة واستوردها في IIS أو ASP.NET Core
  4. أضف الشهادة إلى Trusted Root Certification Authorities على كل جهاز عميل

• أو استخدم Internal PKI (Active Directory Certificate Services)

-------------------------------------------------------------------------------
٣. سياسة كلمات المرور
-------------------------------------------------------------------------------
القيم الافتراضية في appsettings.json:
- الحد الأدنى للطول: 12 حرفاً
- يجب أن تحتوي على: أحرف كبيرة + صغيرة + أرقام + رموز خاصة
- تغيير إجباري كل: 90 يوماً
- حفظ آخر 5 كلمات مرور (عدم إعادة الاستخدام)
- قفل الحساب بعد: 5 محاولات فاشلة
- مدة القفل: 30 دقيقة

للتعديل، غيّر قسم PasswordPolicy في appsettings.json

-------------------------------------------------------------------------------
٤. المصادقة الثنائية (MFA)
-------------------------------------------------------------------------------
• النظام يدعم TOTP (Time-based One-Time Password)
• لتفعيله:
  1. المستخدم يدخل إعدادات حسابه
  2. يمسح QR Code بتطبيق Google Authenticator أو Microsoft Authenticator
  3. يؤكد الرمز الأول
  4. يتم تخزين TfaSecret مشفراً في قاعدة البيانات

⚠️ ملاحظة: الكود الحالي يحتوي على placeholder لـ TOTP
   يجب إضافة مكتبة OtpNet من NuGet وتنفيذ المنطق الفعلي

-------------------------------------------------------------------------------
٥. إدارة الجلسات (Session Management)
-------------------------------------------------------------------------------
• مدة الجلسة الافتراضية: 30 دقيقة عدم نشاط
• عند انتهاء الجلسة، يُطلب من المستخدم تسجيل الدخول مجدداً
• جدول Sessions يسجل كل جلسة نشطة مع عنوان IP ومتصفح المستخدم
• المدير يمكنه إنهاء جلسات مستخدم معين عن بُعد

-------------------------------------------------------------------------------
٦. حماية الملفات المرفقة
-------------------------------------------------------------------------------
• يتم فحص امتداد الملف قبل الحفظ
• الأنواع المحظورة: .exe, .bat, .ps1, .vbs, .js, .dll, .msi, .scr
• الحد الأقصى لحجم الملف: 10 MB
• يتم تخزين الملفات بأسماء عشوائية (GUID) لمنع التخمين
• لا يتم تنفيذ أي ملف مرفق تلقائياً

-------------------------------------------------------------------------------
٧. سجل التدقيق (Audit Log)
-------------------------------------------------------------------------------
• يتم تسجيل كل إجراء مهم تلقائياً
• السجل يتضمن: المستخدم، الإجراء، الكيان، التفاصيل، التاريخ
• السجل غير قابل للتعديل أو الحذف (Append-only)
• للتصدير: SELECT * FROM AuditLog ORDER BY LoggedAt DESC

-------------------------------------------------------------------------------
٨. خطة النسخ الاحتياطي
-------------------------------------------------------------------------------
• نسخ احتياطي يومي كامل (Full Backup) الساعة 02:00 صباحاً
• نسخ تفاضلي كل 6 ساعات
• الاحتفاظ بآخر 30 نسخة كاملة
• تخزين النسخ في موقع منفصل (Off-site)
• اختبار استعادة شهري

لإعداد النسخ الاحتياطي:
1. SQL Server Agent → Jobs → New Job
2. Step: BACKUP DATABASE [TicketingSystem] TO DISK = 'C:\Backups\TicketingSystem_FULL_YYYYMMDD.bak' WITH COMPRESSION
3. Schedule: Daily at 02:00 AM

-------------------------------------------------------------------------------
٩. تقييم المخاطر الدوري
-------------------------------------------------------------------------------
• مراجعة سجلات التدقيق أسبوعياً
• تحديث قائمة الصلاحيات ربع سنوياً
• اختبار اختراق داخلي سنوياً
• مراجعة سياسات الأمان مع فريق الأمن السيبراني
